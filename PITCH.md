## AD.1 SLSA uses provenance as verifiable information that can be used to track an artifact back to where it came from.

## AD.2 SLSA describes higher build levels as providing increasing protection against tampering of the build, provenance or artifact.

## AD.3 SLSA Build Provenance represents build outputs as identified `subject` entries.

## AD.4 Microsoft documents Bicep deployments as idempotent: repeated deployment of the same definition should produce the same resource types in the same state.

## AD.5 Microsoft documents that pipeline execution can depend on previous job success and on conditions such as `succeeded()` and `failed()`.
